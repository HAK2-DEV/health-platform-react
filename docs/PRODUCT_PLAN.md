## 1. 서비스 개요

### 1.1 한 줄 정의
**건강증진 프로그램을 누구나 쉽게 만들고, 함께 참여하며, 데이터로 마무리하는 PWA/모바일 서비스.**

### 1.2 배경 — 왜 만드는가
군·보건소·기업 건강팀의 건강증진 사업 현장에는 반복되는 문제가 있다.

| 문제 | 현실 |
|---|---|
| 참여자 관리 | 종이·엑셀·카톡으로 인증을 일일이 수집·정리 |
| 동기 부여 | 시작은 좋지만 중간에 흐지부지 |
| 데이터 부재 | 종료 후 "잘 됐다"는 정성 보고만 남음 |
| 운영자 번아웃 | 할 일은 많은데 전용 도구가 없음 |

> "운영자도 사람이고, 참여자도 사람입니다. 사람을 사람답게 도와주는 도구가 필요했어요."

### 1.3 북극성(North Star)
> **"누구나 건강 운영자가 될 수 있도록 돕는 도구.
> 함께도 좋고 혼자도 좋다.
> 격려와 도전의 조화로, 건강이라는 재산을 흩어버리지 않도록."**

모든 디자인·기능·카피·마케팅 결정의 기준점.

### 1.4 브랜드
- **태그라인**: "운영은 쉽게, 건강은 단단하게"
- **키워드**: 쉬움 · 단단함 · 동행
- **심볼 컨셉**: "함께 자라는 잎"
- **톤**: 격려와 도전의 조화. 경쟁을 강요하지 않되, 성취를 시각화한다.

### 1.5 왜 '도담'인가 — 네이밍
- **어원**: '도담'은 순우리말 **"도담도담"**에서 왔다. 아이가 별 탈 없이 **건강하게, 꾸준히 자라는 모양**을 뜻하는 말이다.
- **서비스와의 연결**: 건강은 하루아침에 급성장하는 것이 아니라 **매일 조금씩 단단하게 쌓이는** 것이다. "건강이 도담도담 자라도록 돕는다"는 문장이 곧 서비스의 약속이며, 태그라인 **"건강은 단단하게"**·심볼 **"함께 자라는 잎"**·북극성의 "건강이라는 재산을 흩어버리지 않도록"과 정확히 맞물린다.
- **정서·톤**: 다정하고 부드러운 어감이 **격려·동행** 톤과 어울리고, 경쟁보다 꾸준함을 지향하는 게이미피케이션 철학(정원·별자리)과 결이 같다.
- **실용성**: 짧고 부르기 쉬우며, 순우리말이라 친근하고 기억에 잘 남는다. (영문 표기 예: **Dodam**)

## 2. 타깃 사용자

서비스는 **한 명이 두 역할을 오갈 수 있는** 이중 사용자 구조를 갖는다.

### 2.1 운영자 (Health Officer)
- **대상**: 보건소 담당자, 기업 건강팀, 군 의무대, 동호회·소모임 리더
- **핵심 니즈**: 편의성 · 신뢰성 · 운영 부담 최소화 · 결과 보고
- **기대**: "프로그램을 4분 만에 열고, 인증을 자동으로 모으고, 끝나면 리포트가 나온다."

### 2.2 참여자 (Participant)
- **대상**: 일반 직장인, 시민, 군인 등
- **핵심 니즈**: 응원 · 성취 · 소속감 · 연결감 · 간편함
- **기대**: "사진 한 장·숫자 하나로 인증하고, 내 성장을 눈으로 본다."

## 3. 핵심 가치 제안 & 차별점

1. **운영자 진입장벽 최소화** — 4단계 마법사 + 미션 라이브러리(사전 제작 미션)로 "기획 없이도" 프로그램 발행.
2. **분위기 선택형 게이미피케이션** — 프로그램마다 랭킹(도전) / 정원·별자리(비경쟁 성장)를 운영자가 선택.
3. **인증→데이터→리포트의 완결 루프** — 인증이 곧 데이터가 되고, 종료 시 자동 리포트로 이어진다.
4. **테마형 경험** — 프로그램 성격(달리기·금연 등)에 맞춘 전용 홈/연출 제공.
5. **함께 & 혼자의 균형** — 팀·커뮤니티로 함께, 정원·개인기록으로 혼자도 가능.

## 4. 핵심 기능

### 4.1 프로그램 마법사 (운영자)
4단계로 프로그램을 발행한다. 임시저장으로 언제든 이어서 작성 가능.
1. **기본 정보** — 이름·기간·카테고리·표지
2. **분위기(트랙) 정하기** — 피드/랭킹/성장형(정원·별자리)
3. **참여 조건** — 공개 / 승인제 / 초대코드
4. **요약 + 게시**

부가: **라이브러리 프리셋**(예: 3km 달리기 챌린지)에서 원클릭 생성, 지난 기수 **복제**.

### 4.2 미션 라이브러리 (운영자)
- 카테고리 **8종**(운동·달리기·식단·공감·마음관리·수면·금연·기타) × 사전 제작 미션. *(초기 7종에서 '달리기'를 '운동'에서 분리해 8종으로 확장 — 마이그 136 달리기 테마)*
- 미션마다 AI 일러스트 아이콘 자동 표시.
- "묶음 통째로 추가" 지원 + 직접 미션 자유 생성.
- 미션별 **메인/서브** 지정, 스케줄(평일/주말/특정 요일) 설정.

### 4.3 인증 흐름 (참여자)
- **사진** 업로드(운동·식단 등) / **숫자** 기록(걸음·러닝 km·수면 등) / **소감** 한 줄.
- 미션별 입력 항목·배점 구성. 인증마다 점수 적립.
- **자동 승인** 또는 **운영자 심사(MANUAL)** 선택. 심사함에서 일괄 검토.

### 4.4 격려 시스템 (게이미피케이션)
운영자가 프로그램별로 트랙 선택.
- **랭킹(도전)** — 포디움, 14일 추세, 기간 필터, 순위 변동 히스토리. 점수 방식(합계/평균) 선택.
- **정원·별자리(비경쟁 성장, 설계 확정)** — "물=인증, 햇빛=출석" 메타포. 4×4 정원, 16종 꽃 풀, 12개 별자리, 5단계 성장, 연속·누적 보너스, 도감. "각자의 정원, 각자의 별자리."

### 4.5 팀 기능
- 앱 내 **초대 전용** 팀, 팀장 위임.
- 점수 방식 운영자 선택(합계+평균 / 평균).
- "내 팀 카드"로 팀 현황 확인.

### 4.6 커뮤니티 (피드)
- 게시판(응원·인증·자유·공지) 칩, 댓글 스레드, 좋아요, 공지 고정.
- 운영자 검토 대기 배너·심사 진입, 커뮤니티 관리 페이지.

### 4.7 퀴즈
- 건강 퀴즈(객관식·OX·서술형) 출제·풀이, 단계형(스텝퍼) 풀이 UI, 결과·채점·정답 공개.
- 퀴즈 라이브러리 콘텐츠 확충 중.

### 4.8 운영자 도구 (데이터·운영)
- **3대 지표**: 참여율 · 다양성 · 꾸준함.
- **시간대 패턴**, **미션별 인기도**, **휴면 참가자 추적**, **주간 하이라이트**.
- 참여자 드릴다운(미션·인증·게시글·점수·댓글), 참가자 추세.
- **종료 리포트**(완주 명단·전 기간 추이 등) — 사업 결과 보고용.
- **화면 체류 자체 분석**(ADMIN 전용) — 자체 호스팅(외부 분석 도구 미사용).

### 4.9 테마형 프로그램
- **달리기 테마** — 전용 RunningHome(히어로·추천 페이스·주간 스트릭 도장 연출·주요 기록 요약·지도 위 코스 진행률 시각화·미션/퀴즈/커뮤니티 진입).
- **금연 테마** — 히어로·기분 체크·응원 게시판 등 변형.

### 4.10 고객 지원
- **1:1 문의 게시판** — 비공개+비밀번호, 댓글 스레드, 관리자(ADMIN) 답변.
- **운영자 가이드**, 약관/개인정보처리방침, PWA 설치 가이드.

## 5. 정보 구조(IA) & 주요 흐름

### 5.1 최상위 내비게이션
- **대시보드** — 오늘의 활동·대표 프로그램·활동 요약
- **프로그램** — 참여중/운영중, 둘러보기(공개 프로그램)
- **기록** — 내 인증 기록
- **랭킹**, **알림**, **프로필**(활동·설정·계정)

### 5.2 프로그램 상세 탭
개요 · 미션 · 퀴즈 · 커뮤니티 · 랭킹(성장). (달리기 테마는 탭 대신 RunningHome 대시보드로 통합)

### 5.3 대표 사용자 흐름
- **운영자**: 로그인 → 마법사(4단계) → 미션 라이브러리 추가 → 발행 → 심사/커뮤니티 운영 → 통계 → 종료 리포트.
- **참여자**: 둘러보기/초대 → 참여(공개·승인·코드) → 오늘의 미션 인증 → 점수·랭킹·정원 확인 → 커뮤니티·퀴즈 참여.

## 6. 기술 아키텍처

### 6.1 스택
| 영역 | 기술 |
|---|---|
| 프론트엔드 | React 19 · Vite 8 · Tailwind CSS v4 · React Router 7 |
| 상태/데이터 | TanStack React Query 5 |
| 애니메이션 | framer-motion 12 |
| 백엔드 | Supabase (PostgreSQL · Auth · Storage · **RLS**) |
| 인증 | Kakao · Google(GIS) OAuth |
| 모바일 | **PWA**(현재, vite-plugin-pwa) · **Capacitor 8**(네이티브 출시 예정) |
| 모니터링 | Sentry |
| 이미지 | browser-image-compression · react-easy-crop |

### 6.2 데이터·보안 원칙
- 모든 접근 제어는 **Row Level Security(RLS)** 기반. 집계·민감 조회는 SECURITY DEFINER RPC로 최소 노출.
- DB 변경은 **번호 마이그레이션**으로 관리(현재 151개). **프로드 먼저 적용 → 코드 배포**, 컬럼/함수 **하위호환** 원칙.

### 6.3 배포·안정성
- 웹: Vercel 배포(PWA). 청크 404 자가복구, 마이그레이션-코드 순서 안전 배포.
- 자체 호스팅 분석(외부 추적 도구 미사용) — 개인정보·통제 관점 결정.

### 6.4 UI/디자인 스펙 — 레이아웃·라운딩·간격·아이콘
*(단일 출처: `src/index.css`의 `@theme` 토큰 + [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md). 아래는 구현 관용 요약)*

**레이아웃 배치**
- **모바일 우선**. 페이지 컨테이너 `max-w-4xl mx-auto px-3 sm:px-4`(좌우 여백 12→16px).
- 하단 **5탭 BottomTabBar**, 본문 하단 `pb-24`로 탭 가림 방지. 상단 헤더 `sticky`(좌: 뒤로 / 중앙: 제목 / 우: 액션).
- 카드 세로 간격 `space-y-4`(섹션)·`space-y-3`(카드). 다중 카드는 `grid grid-cols-N gap-3`, 균등 높이는 `items-stretch`.
- **테마 화면**: 달리기는 탭바 대신 RunningHome 단일 스크롤 대시보드(히어로→페이스/스트릭→요약→코스맵→진입 카드→배너).
- 라우트 전환 시 `scrollTo(0,0)`, safe-area 패딩, 가로 스와이프 뒤로가기 차단.

**모서리 라운딩(Radius)**
- 토큰: `rounded-card` **24px**(기본 카드) · `rounded-card-lg` **28px**(강조 카드) · `rounded-pill` **9999px**(칩·뱃지·탭·CTA).
- 콤팩트 카드·오버레이·이미지 컨테이너·모달 상단은 `rounded-2xl`(**16px**) 관용. 아이콘 원형 배경은 `rounded-full`. 진행 바 등은 `rounded-full`.

**간격(Spacing) — 4px 베이스, 6단계**
- **4 / 8 / 12 / 16 / 20 / 24**(Tailwind 1~6)만 사용해 톤 일관.
- 아이콘↔텍스트 `gap-1~1.5` · 칩·인라인 `gap-2` · 카드 내 요소(썸네일↔본문) `gap-3`.
- 카드 패딩 `sm=p-3` / **`md=p-4`(기본)** / `lg=p-5` · 모달·빈 상태 `p-6`.

**아이콘(Icons) — 2계층**
- ① **시스템 아이콘** `lucide-react`(UI 액션·메타·내비, `strokeWidth≈2`). ② **브랜드 일러스트 PNG**(미션·카테고리·러닝 아이콘 등) — `AssetImg`로 로드, 실패 시 `onError`로 lucide **fallback**.
- 관용 크기: 내비 카드 **21×21** · 아이콘 원형 배경 **w-9(36px)** · 메타 아이콘 **w-3(12px)** · 헤더 액션 **w-5(20px)**.
- 카테고리 이모지·액센트색(운동·달리기·식단·공감·마음관리·수면·금연·기타)은 `CATEGORY`·`programVisuals.CATEGORY_COLORS`와 연동.

**그림자 · 버튼 · 타이포(요약)**
- 그림자: `shadow-soft`(기본) / `shadow-elevated`(호버·강조) / `shadow-fab`(+버튼) — 그린 틴트.
- Primary CTA: emerald→teal 그라데이션 **pill** 버튼. 비활성 `disabled:opacity-40`.
- 글꼴 **Pretendard Variable**(자간 -0.01em), 본문 `text-sm`=15px 주력, 섹션 제목 `text-lg` bold.
- 브랜드색 **Emerald**(Primary `#059669`/`#10b981` · Accent `#34D399` · Bg `#ECFDF5` · Ink `#073B33`).

> 전체 디자인 토큰·타입 스케일·컴포넌트 프리미티브(Badge·IconBox·Card·Modal·EmptyState 등)는 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)가 정본.

## 7. 운영 정책

- **참여 방식**: 공개 / 승인제 / 초대코드.
- **인증 승인**: 프로그램별 자동/수동(MANUAL) 선택.
- **약관·개인정보처리방침** 동의 흐름 적용. 정식 출시 시 사업자 등록 검토.
- **콘텐츠 검토**: 커뮤니티 게시글 운영자 심사·검토 대기 관리.

### 진행 현황 요약
- **완료·배포**: 마법사·미션 라이브러리·인증·랭킹·커뮤니티·퀴즈·팀·1:1 문의·종료 리포트·달리기 테마 홈·주간 스트릭 연출·프로그램 라이브러리(1차).
- **설계 확정/진행 중**: 정원·별자리 게이미피케이션, 금연 테마 세부, 퀴즈 콘텐츠 확충, 네이티브 정식 출시.
- **검토 대기**: 운영자 레벨/칭호·온도 랭킹, 초대 공유 네이티브 연동, 완주 기준 재검토.

## 9. 성공 지표(KPI) — 제안

- **활성화**: 발행된 프로그램 수, 프로그램당 활성 참여자 수, 주간 인증 완료율.
- **지속성**: 연속 인증(스트릭) 유지율, 중도 이탈(휴면) 비율, 기수 재개설·복제 비율.
- **운영자 만족**: 발행 완료 소요 시간, 종료 리포트 활용률.
- **품질**: 오류율(Sentry), 핵심 화면 체류·완주 경험.

*(베타 단계에서는 정량 목표보다 정성 피드백·핵심 지표 계측 체계 확립을 우선.)*

## 10. 리스크 & 향후 과제

- **콜드 스타트**: 초기 공개 프로그램·콘텐츠 부족 → 라이브러리·프리셋·데모로 완화.
- **확장성**: 공개 프로그램 전량 클라이언트 조회 → 규모 확대 시 서버측 필터·페이지네이션 전환 필요.
- **운영 부담 vs 자동화**: 수동 심사의 신뢰성과 편의성 균형(현재 MANUAL 유지).
- **정식 출시 준비**: 스토어 심사·사업자 등록·개인정보 처리 고도화.
