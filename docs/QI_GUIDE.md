> **버전**: 2026-06-13 (mvp-v2)
> **대상**: 품질 검수(QI) 담당자
> **참고**: 시스템 요구사항 상세는 [`SSRD.md`](./SSRD.md)
> **변경 안내**: 2026-06-02 최초본 이후 기능이 많이 추가됨 — **3.11 신규 기능** 절을 먼저 보면 빠릅니다.

## 0. 한 줄 요약

**건강증진 프로그램을 운영자가 직접 설계하고, 참가자가 미션을 인증하면 점수·랭킹·피드가 자동으로 따라오는 모바일 우선 PWA 웹앱입니다.**

---

## 1. QI 시작 전 알아두실 것

### 1.1 기술 스택
- **클라이언트**: React + Vite 빌드, PWA (모바일 홈 화면 추가 가능)
- **서버 / DB**: Supabase (Postgres + Auth + Storage)
- **인증**: 이메일 + 비밀번호 + **소셜 로그인(카카오·구글)**. 네이버 미진행
- **언어 / 시간**: 한국어 단일 / KST (Asia/Seoul)
- **브라우저 권장**: 모바일 Chrome / iOS Safari / 데스크톱 Chrome (최신)

### 1.2 환경 / 접속
- **운영 URL**: (담당자에게 별도 안내)
- **테스트 계정**: (담당자에게 별도 안내 — 운영자 1, 참가자 2 권장)
- **로컬 개발**: `npm install && npm run dev` → `http://localhost:5173`

### 1.3 사용자 권한 모델 (가장 중요)
같은 사람이 **프로그램 A의 운영자** + **프로그램 B의 참가자**가 동시에 될 수 있습니다. "운영자/참가자"는 사람 단위가 아니라 **프로그램 단위로 결정**됩니다.

| 역할 | 결정 기준 |
| --- | --- |
| **운영자** | `programs.owner_id = <내 id>` (내가 만든 프로그램) |
| **참가자** | `program_participants.user_id = <내 id> AND status='ACTIVE'` |

## 2. 사용자 흐름 (Big Picture)

### 2.1 처음 사용자
```text
1. /signup 회원가입 (이메일 + 비밀번호)
2. /nickname-setup 닉네임 입력 (7일 변경 잠금)
3. /dashboard 메인 화면 진입
4. 두 가지 선택:
   - 운영자: 우하단 + (FAB) → 마법사로 프로그램 생성
   - 참가자: BottomTab 「프로그램」 → 둘러보기에서 공개 프로그램 참여
```

### 2.2 일일 사용 (참가자)
```text
대시보드 → 「✨ 오늘의 미션」 → 각 미션 「인증」 클릭
  → 풀스크린 인증 페이지에서 사진/숫자/소감 입력 → 제출
  → 자동(AUTO) 미션은 즉시 점수, 수동(MANUAL)은 운영자 심사 대기
  → 대시보드/프로그램 상세에서 점수·랭킹·피드 확인
```

### 2.3 일일 사용 (운영자)
```text
대시보드 또는 프로그램 탭에서 본인 프로그램 진입
  → 「개요」 탭에서 점수 요약 + 운영자 패널
  → 「운영자 패널」에서 4가지 액션:
     - ✏️ 프로그램 수정
     - 📝 개요 글 작성/수정 (마크다운 안내문)
     - 📋 게시물 관리 (퀴즈 생성/관리)
     - ✅ 인증 심사 (MANUAL 미션의 승인/반려)
     - 📊 참여자 통계
  → 「미션」 탭에서 미션 추가/수정/삭제
  → 「커뮤니티」 탭에서 참여자들의 피드 확인 (좋아요/댓글 가능)
```

## 3. 화면별 기능 설명

### 3.1 BottomTab (모든 로그인 화면 하단)

5개 탭: **🏠 홈** · **📋 프로그램** · **🏆 랭킹** · **🔔 알림** · **👤 프로필**

- 일부 풀스크린 화면(미션 인증, 퀴즈 풀이, 마법사)에서는 자동으로 숨겨집니다.

### 3.2 🏠 대시보드 (`/dashboard`)
- 그라데이션 헤더 + 인사말 + 알림 종(읽지 않은 알림 수 배지)
- **통계 4카드**: 운영 중 / 참여 중 / 참여 예정 / 누적 포인트
- **✨ 오늘의 미션**: 프로그램별 그룹화, 묶음 카드 + 단독 미션, 3개 이상이면 전체보기
- **🌿 운영중인 프로그램**(구 「내 프로그램」) / **🎯 참여 중인 프로그램**: 각 2개까지 + 전체보기

### 3.3 📋 프로그램 (`/programs`)
- 상단 검색바 (이름/설명 클라이언트 필터)
- 3섹션:
  1. **🎯 참여 중인 프로그램** (sky 파스텔 박스)
  2. **🌿 운영중인 프로그램** (운영자 시점, 구 「내 프로그램」)
  3. **🔍 둘러보기** (공개 + 비참여 프로그램) — 미리보기 3개 + 「전체 둘러보기」 모달(카테고리 필터·정렬)
- **우하단 FAB ➕** → 마법사 진입 (베타: 1인당 운영 프로그램 2개 제한, ENDED 시 슬롯 반환)

### 3.4 🏆 랭킹 (`/rankings`)
- 참여 중 프로그램 칩 선택
- 기간 토글 (전체/7일/30일, `period_filter_enabled` 시)
- 본인 요약 카드 + 14일 sparkline (`trend_enabled` 시)
- 포디움 2-1-3 (참여자 3명 이상 + `podium_enabled` 시)
- 평면 랭킹 + 본인 위치 점프 floating 버튼
- **랭킹이 꺼진 프로그램은 칩에서 숨겨집니다.**

### 3.5 🔔 알림 (`/notifications`)
- 읽지 않은 알림 emerald 강조 + 좌측 점
- 클릭 시 읽음 + 연결 페이지로 이동
- 상단 우측 "모두 읽음 (N)" 일괄 처리
- 우측 휴지통으로 개별 삭제

### 3.6 👤 프로필 (`/profile`)
- 아바타 + 닉네임 (7일 쿨다운 후 변경 가능)
- 카메라 버튼 → 1:1 원형 크롭 → 업로드
- 📖 **운영자 가이드** 진입 → `/operator-guide` (주제 탭별 스크린샷 워크스루)
- 📊 내 인증 현황 진입 카드 → `/profile/activity`
- 🔔 **알림 설정** → `/profile/notifications-settings` (type별 ON/OFF)
- 🛡️ **계정 설정** → `/profile/account-settings` (비밀번호 변경·회원 탈퇴)
- 이메일 표시 / 로그아웃

### 3.7 📊 내 인증 현황 (`/profile/activity`)
- 프로그램 칩 (참여 중)
- 4지표: 누적 점수 / 누적 인증 / 활동 일수 / 마지막 활동
- 14일 활동 막대 차트
- 진입 카드: 🎯 미션별 분포 / 📝 인증 기록 (묶음별 → 개별 카드)

### 3.8 프로그램 상세 (`/programs/:id`) — 5탭 핵심 화면

#### Hero 카드 (탭 위)
- 좌측 표지 사진 (없으면 카테고리 이모지 fallback)
- 진행중/예정/임시저장 배지
- 프로그램명, 기간, 진행률 바, 참여자 수, 내 순위

#### 탭 5개 — **랭킹은 운영자가 OFF 한 프로그램에서는 숨겨집니다**

| 탭 | 참가자 시점 | 운영자 시점 |
| --- | --- | --- |
| **개요** | 점수 요약 (오늘/누적) + 안내(개요 글) | 위 + 운영자 패널 + 초대 링크 카드 |
| **미션** | 미션 목록 (묶음 그룹화, 4개+ 시 전체보기) | 위 + "+ 미션 추가" 버튼 + 수정/삭제 + **미션 아이콘 설정** |
| **퀴즈** | 풀 수 있는 퀴즈 목록 | "게시물 관리에서 퀴즈를 생성하세요" 안내 (직접 작성 또는 **퀴즈 라이브러리**에서 선택) |
| **커뮤니티** | 피드 (좋아요/댓글, 댓글은 아이콘 클릭 시 펼침) | 동일 (운영자도 댓글 작성·모든 댓글 삭제 가능) |
| **랭킹** | 순위 + 내 위치 | 동일 |

#### 미션 카드 동작
- 오늘 한도 충족 + 승인 완료: **✓ 완료** 배지
- 한도 충족 + 심사 대기: **⏳ 심사 대기** 배지
- 그 외: **인증/업로드/기록** 등의 액션 버튼
- 운영자: 카드 우측에 ✏️ 수정 / 🗑 삭제

### 3.9 미션 인증 (`/programs/:programId/missions/:missionId`)
- 풀스크린 (BottomTab 숨김)
- 카테고리 별 그라데이션 배경
- 미션 요구사항에 따라 사진/숫자/소감 입력란 노출
- **입력별 점수·필수/선택** (신규): 입력 종류별로 점수와 필수 여부를 따로 둘 수 있음
  - 예) 사진 7점(필수) + 소감 3점(선택) → 사진만 제출 7점, 소감까지 작성 시 10점
  - 필수 입력 미작성 시 제출 차단(에러 위치로 자동 스크롤), 선택 입력은 건너뛰기 가능
  - 레거시 미션(입력별 점수 미설정)은 기존 단일 점수로 동작 (하위호환)
- **이미지**: 5MB 이하 선택, 업로드 직전 **1280px·0.6MB 이하**로 자동 압축
- 피드 공개 토글 (`feed_enabled` 시)
- 하단 고정 [취소] [인증 제출] 버튼

### 3.10 마법사 (`/programs/new`)
4단계: 기본 정보 → 옵션 → 참여 조건 → 요약·발행
- 각 단계 임시 저장 가능 / 임시 저장 시 DRAFT 상태로 대시보드 복귀
- **참여 조건 3종**: 공개(FREE) / 승인제(APPROVAL) / 초대코드(INVITE_CODE) + 입장 질문 설정
- **게이미피케이션 트랙 선택**(신규): 랭킹 / 정원 / 별자리 중 선택 (트랙별 동기부여 메타포)
- 4단계에서 "프로그램 만들기" → PUBLISHED
- **베타 제한**: 1인당 운영 프로그램 **2개**까지 (관리자 면제, 종료(ENDED) 시 슬롯 반환)

### 3.11 신규 기능 (2026-06-02 이후 추가) ⭐

- **운영자 가이드 페이지** (`/operator-guide`): 마법사·운영자 패널·미션·퀴즈를 **주제 탭별 스크린샷 워크스루**로 안내. 첫 프로그램 발행 직후 **환영 캐러셀**(4슬라이드) 1회 노출.
- **미션 아이콘**: 미션 생성·수정 시 **기본 아이콘 갤러리** 선택 또는 **직접 업로드**(1:1 크롭).
- **퀴즈 라이브러리**: 직접 작성 외에, 대상자별(**군인·근로자**) 사전 제작 퀴즈를 골라 추가. 각 문항에 **해설·출처 링크** 포함.
- **사후 점수 제외(운영자)**: AUTO로 즉시 승인된 부적절한 인증을 **점수 제외** → 점수 회수 + 반려(REJECTED) 처리로 피드에서도 제외(기록·사진은 보존). 참가자에게 알림. (베타는 복구 UI 미제공 — 재승인으로 복구)
- **참여 예약**: 시작 전 프로그램에 미리 참여 신청 → 「참여 예정」으로 표시.
- **알림 설정** (`/profile/notifications-settings`): 알림 type별 ON/OFF. OFF 시 목록·뱃지에서 즉시 제외.
- **계정 설정** (`/profile/account-settings`): 비밀번호 변경 · 회원 탈퇴.
- **댓글 lazy 로딩**: 피드는 댓글 수만 표시, 아이콘 클릭 시 해당 게시물 댓글을 그때 불러옴(부하 절감).
- **약관 동의 흐름 / PWA 설치 가이드 / Sentry 오류 수집** 적용됨.

## 4. 핵심 테스트 시나리오 (10개)

### S-01: 회원가입 → 닉네임 → 대시보드 (해피 패스)
1. `/signup` 진입 → 이메일/비밀번호 입력 → 회원가입
2. 자동으로 `/nickname-setup` 이동
3. 닉네임 입력 (중복 체크 실시간) → 시작하기
4. 대시보드 진입 + 인사말 + 통계 0/0/0/0 표시
**기대**: 4단계 모두 정상, 에러 없음.

### S-02: 운영자 프로그램 생성 (마법사 4단계)
1. 대시보드 → 「프로그램 생성하기」(FAB) → Step1
2. 이름/기간/카테고리/목표 입력 → 다음
3. Step2 옵션 토글 5종 → 다음
4. Step3 참여 방식 선택 (FREE 권장) → 다음
5. Step4 요약 확인 → 「🎉 프로그램 만들기」
**기대**: PUBLISHED 상태로 대시보드 복귀, 「운영중인 프로그램」에 표시. 첫 발행이면 **환영 캐러셀** 1회 노출.

### S-03: 운영자 미션 추가 (추천 묶음)
1. 새 프로그램 상세 → 미션 탭 → 「+ 미션 추가」
2. 추천 미션 라이브러리 모달 → 묶음 선택
3. 묶음 내 미션 선택 + 점수/한도 조정 → 추가
**기대**: 미션 탭에 묶음 카드 노출, 묶음 진입 시 미션들 표시.

### S-04: 참가자 참여 + 미션 인증 (AUTO)
1. 참가자 계정으로 로그인 → 「프로그램」 → 둘러보기에서 공개 프로그램 「참여」
2. 프로그램 상세 진입 → 미션 탭 → 「인증」
3. 풀스크린 인증 페이지 → 사진 선택 (5MB 이하) → 제출
**기대**: 즉시 APPROVED, 점수 카드의 오늘/누적 값 증가, 미션 카드에 「✓ 완료」.

### S-05: 운영자 인증 심사 (MANUAL)
1. 운영자가 미션의 `verification_type='MANUAL'`로 설정
2. 참가자가 인증 → status `PENDING_REVIEW`로 저장
3. 운영자 패널 → 「✅ 인증 심사」 진입 → 묶음/미션 진입
4. 인증 카드 「승인」 또는 「반려」 클릭
**기대**: 승인 시 점수 부여 + 알림 / 반려 시 알림.

### S-06: 중복 사진 차단
1. 같은 사진을 두 번 다른 미션에 인증 제출
**기대**: 두 번째 제출에서 "이미 인증에 사용한 사진이에요" 에러 (SHA-256 해시 매칭).

### S-07: 커뮤니티 피드
1. 두 참가자가 같은 프로그램에 참여
2. 참가자 A가 피드 공개로 인증 제출 (`feed_enabled=true` 프로그램에서)
3. 참가자 B가 ProgramDetail → 커뮤니티 탭 진입
**기대**: A의 게시물 표시, B가 좋아요/댓글 가능, A에게 알림 도달.

### S-08: 퀴즈 생성 + 풀이 + 채점
1. 운영자 → 「📋 게시물 관리」 → 「퀴즈 만들기」
2. 객관식 + OX + 서술형(AUTO) + 서술형(MANUAL) 한 문제씩 생성
3. 참가자가 퀴즈 풀이 제출
4. AUTO 문제는 즉시 채점 → 점수 반영, MANUAL은 PENDING
5. 운영자가 결과 페이지에서 MANUAL 채점
**기대**: 점수 ledger에 반영, 랭킹 갱신.

### S-09: 랭킹 OFF 동작
1. 운영자가 ProgramEditModal에서 랭킹 표시 OFF → 저장
2. 같은 프로그램의 ProgramDetail 진입
3. `/rankings` 페이지 진입
**기대**: ProgramDetail 탭바에서 「랭킹」 사라짐 + `/rankings` 칩에서도 사라짐. Hero 카드 "내 순위" 표시도 사라짐.

### S-10: 개요 글 작성 + 마크다운 표시
1. 운영자 → 「📝 개요 글 작성」 → OverviewEditModal
2. 편집 탭에 마크다운 입력 (**굵게**, [링크](https://...), - 리스트, > 인용)
3. 미리보기 탭 전환 → 마크다운 렌더링 확인 → 저장
4. 모든 참여자가 개요 탭의 「📝 안내」에서 렌더링된 글 확인
**기대**: 마크다운 정확히 렌더, 운영자에게만 ✏️ 수정 버튼 노출.

### S-11: 입력별 점수·필수/선택 미션 (신규)
1. 운영자: 미션 생성 → 사진 7점(필수) + 소감 3점(선택)으로 설정 후 발행
2. 참가자: 해당 미션 인증 → **사진만** 제출 → 7점 부여 확인
3. 다시 인증 → 사진 + 소감 작성 제출 → 10점 부여 확인
4. 필수(사진)를 비우고 제출 시도 → **차단 + 에러 위치로 자동 스크롤**
**기대**: 점수 부여가 입력 조합대로 정확, 필수 미작성 차단.

### S-12: 퀴즈 라이브러리 추가 (신규)
1. 운영자 → 게시물 관리 → 퀴즈 만들기 → **퀴즈 라이브러리** → 대상자(군인/근로자) 선택
2. 미리보기에서 문항·해설·**출처 링크** 확인 → 추가
**기대**: 선택한 퀴즈가 프로그램에 등록, 참가자 풀이/채점 정상.

### S-13: 사후 점수 제외 (신규)
1. AUTO 미션을 참가자가 인증 → 즉시 승인·점수 부여
2. 운영자가 해당 인증을 **점수 제외**(사유 입력)
3. 랭킹/누적 점수에서 회수되고 피드에서도 사라지는지 확인 + 참가자 알림 도달 확인
**기대**: 점수 즉시 회수, 게시물 피드 제외(기록·사진은 보존), 알림 발송.

### S-14: 운영자 가이드 · 알림 설정 (신규)
1. 프로필 → **운영자 가이드** → 주제 탭 전환하며 스크린샷 안내 확인
2. 프로필 → **알림 설정** → 특정 type OFF → 해당 알림이 목록·뱃지에서 즉시 사라지는지 확인
**기대**: 가이드 정상 표시, 알림 OFF 즉시 반영.

## 6. 자주 발생할 만한 검수 포인트

### 6.1 데이터 일관성
- 미션 인증 직후 다른 페이지(랭킹, 본인 활동, 피드)의 점수/카운트가 즉시 갱신되는가?
  - 정상: mutation onSuccess에서 invalidateQueries 적용됨
  - 비정상: 5분 이상 지나야 갱신 — staleTime 5분 설정이라 즉시 갱신은 mutation 트리거에 의존

### 6.2 권한 분리
- 참가자가 운영자 전용 URL(`/programs/:id/posts`, `/reviews`, `/stats`)을 직접 입력하면 어떻게 동작하는가?
  - 정상: 운영자 권한 체크 후 "운영자만 가능" 안내 또는 자동 이동

### 6.3 캐시 / Stale 데이터
- 두 탭을 동시에 열고 한쪽에서 변경 후 다른 쪽에서 5분 안에 돌아오면 어떻게 동작하는가?
  - 의도: staleTime 5분이라 5분 안에는 캐시 사용 → 다른 mutation이 invalidate 안 한 데이터는 stale 가능
  - 새로고침 (F5)으로 강제 갱신 가능

### 6.4 RLS / 데이터 격리
- 프로그램 A 참가자가 프로그램 B의 인증/피드/랭킹을 볼 수 있는가?
  - 정상: 못 본다 (RLS 차단)

### 6.5 모바일 UX
- 모바일에서 미션 인증 페이지의 입력 필드 클릭 시 자동 zoom-in이 안 일어나는가?
  - 정상: `font-size: 16px` 이상 적용으로 iOS Safari zoom 차단

### 6.6 PWA 동작
- 홈 화면에 추가 후 오프라인 상태에서 진입하면 어떻게 동작하는가?
  - 정상: 캐시된 자산으로 빈 페이지 표시 (실제 데이터는 fetch 실패)
  - 새 배포 후 진입 시 자동 업데이트

### 6.7 이미지 압축
- 5MB 큰 사진 업로드 후 Storage에 저장된 파일 크기는?
  - 정상: 1MB 이하 JPEG로 압축됨
- 이미지 압축이 실패해도 업로드는 되는가?
  - 정상: 원본으로 fallback (안전 장치)

### 6.8 마이그레이션 동기화
- 신규 컬럼/인덱스 추가 후 클라이언트가 이전 버전이면 어떻게 동작하는가?
  - 정상: 신규 컬럼 없이도 기본 동작 유지 (마이그레이션은 backward-compatible로 설계)

## 7. 알려진 제약 / 의도된 한계

### 7.1 한도 (Supabase Free 플랜)
| 항목 | 한도 | 의미 |
| --- | --- | --- |
| 월 Egress | 5 GB | 이미지 압축 적용 후 MAU 200-300명까지 안전 |
| Storage | 1 GB | 인증 사진 1000장 정도 (1MB 평균) |
| DB Size | 500 MB | 텍스트 위주라 수 년간 여유 |
| 동시 Connection | 60 | 동시 활성 50명 이상에서 위험 |
| RAM (NANO) | ~0.5 GB | 동시 활성 30-50명에서 한계 |

### 7.2 의도된 제약
- 닉네임 7일 변경 잠금 (도용 방지)
- 같은 사진 같은 사용자 재사용 차단 (SHA-256)
- DRAFT 프로그램 클릭 시 마법사 재진입 (상세 페이지 직진 X)
- 마법사 Step2 토글 OFF면 하위 옵션 자동 OFF (포디움/추세/기간필터)
- 모든 모달은 ESC 키 또는 외부 클릭으로 닫힘

### 7.3 미구현 / 후속 마일스톤
- 패널티 (감점 정책)
- 신체 지표 (체중/체지방/골격근량)
- 점수 시뮬레이션
- 연속 참여 보너스
- AI 미션 추천 / AI 인증 판별
- 결제 시스템 (수동 운영)
- 다국어 (한국어만)
- 네이티브 앱 (베타는 PWA, Capacitor 셋업 완료 — 정식 출시 시 스토어 배포 예정)
- 다중 역할 시스템 (admin 별도 분리 안 됨)
- 게이미피케이션 정원/별자리 트랙은 선택 가능하나 시각 연출은 단계적 적용 중 (랭킹 트랙이 기본 안정)

### 7.4 알려진 동작
- ProgramDetailPage 첫 진입 시 React Query staleTime 5분 — 다른 사용자가 동시 작업하면 5분간 갱신 안 될 수 있음. 새로고침으로 강제 갱신 가능.
- 이미지 압축이 Web Worker로 동작 — 큰 사진은 1-3초 압축 시간 (사용자에게 indicator 표시 추가 권장).
- 알림은 polling 방식 (실시간 push 미구현). 페이지 진입 시 fetch.
- 피드 댓글은 200자 제한.
- 개요 글 5000자 제한.
- 미션은 program별 한도 없음 (운영자가 자유롭게 추가).

## 8. 버그 리포팅 가이드

### 8.1 보고 시 포함할 정보
1. **재현 경로**: URL + 클릭 순서
2. **계정 권한**: 운영자/참가자 + 프로그램 ID
3. **브라우저**: 종류 + 버전 + 모바일/데스크톱
4. **기대 동작 vs 실제 동작**
5. **에러 메시지**: 화면 텍스트 + 콘솔 (F12 → Console)
6. **스크린샷 또는 영상**
7. **시간**: 정확한 시각 (서버 로그 매칭용)

### 8.2 심각도 기준
- **Critical**: 데이터 손실, 보안 노출, 결제 오류, 핵심 흐름 차단
- **High**: 주요 기능 동작 안 함, 권한 분리 실패
- **Medium**: 일부 기능 오작동, UX 혼란
- **Low**: 시각적 오류, 오타, 사소한 불편

### 8.3 비기능 검수 우선순위
1. **권한 분리 (RLS)** — 참가자가 운영자 데이터 보면 안 됨
2. **데이터 일관성** — mutation 후 다른 화면에 즉시 반영
3. **모바일 UX** — 터치 영역, 키보드 입력, 스크롤
4. **이미지 처리** — 압축, 업로드, 표시
5. **성능** — 초기 로딩, 페이지 전환 (체감 2초 이내)
6. **에러 처리** — 네트워크 실패, 권한 거부, 입력 검증
