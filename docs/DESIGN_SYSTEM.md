## 2. 타입 스케일 (Type Scale)

토큰으로 **본문 기본(text-sm)을 15px로 상향**한 게 핵심. text-sm 이 본문·댓글·알림의 주력(약 367곳)이라 한 줄로 전반 가독성이 올라감.

| 클래스 | 크기 | line-height | 용도 |
| --- | --- | --- | --- |
| `text-xs` | **12.5px** (토큰) | 1.5 | 보조 라벨, 메타, 칩 |
| `text-sm` | **15px** (토큰, 본문 기본) | 1.55 | 본문·댓글·알림·설명 — **주력** |
| `text-base` | 16px | 기본 | 카드 제목, 입력 |
| `text-lg` | 18px | 기본 | **섹션 제목(h2)** |
| `text-xl` | 20px | 기본 | 강조 제목 |
| `text-2xl` | 24px | 기본 | 대제목, 통계 숫자, 로고(헤더) |
| `text-3xl` | 30px | 기본 | 스플래시·로그인 로고 워드마크 |
| `text-[11px]` / `clamp(11px,3vw,13px)` | 11~13px | — | 마이크로 라벨(통계 카드 등, 자동 축소) |

> 모바일 input 은 `@media(max-width:640px)` 에서 **16px 강제** — iOS Safari 포커스 자동 줌 방지.

## 7. 간격 (Spacing) — 4px 베이스

전용 spacing 토큰은 **없음.** **Tailwind 기본 스케일(1 = 0.25rem = 4px)** 을 쓰되, 코드에 굳어진 관용이 있다. (`App.css` 의 `--spacing-xs/sm/md/lg` 는 레거시 — 사용 금지.)

| 감각 | px | Tailwind | 주 용도 |
| --- | --- | --- | --- |
| micro | 4 | `1` · `gap-1` | 아이콘+텍스트, 라벨 묶음(`space-y-1`) |
| tight | 8 | `2` · `gap-2` | 칩·인라인, 폼 필드(`space-y-2`), 통계 그리드 `gap-2` |
| base | 12 | `3` · `gap-3` · `p-3` | 카드 내부 요소(썸네일↔본문), 카드 리스트(`space-y-3`), 콤팩트 패딩 |
| comfortable | 16 | `4` · `p-4` | **섹션 세로 간격 `space-y-4`**, 섹션 헤더 `mb-4`, 카드 패딩 기본 |
| loose | 20 | `5` · `p-5` | 패널·피처 카드, 피드 간격(`space-y-5`) |
| section | 24 | `6` · `p-6` | 모달·풀스크린·빈 상태 컨테이너 패딩 |

### 관용 규칙 (de-facto)
- **페이지 좌우 여백:** `px-3 sm:px-4` (모바일 12 → sm 16)
- **섹션 사이:** `space-y-4`
- **섹션 헤더 아래:** `mb-4`
- **카드 패딩:** `Card` 프리미티브로 표준화 — `padding="sm"`=`p-3`(12) / `"md"`=`p-4`(16, **기본**) / `"lg"`=`p-5`(20)
- **카드 안 요소 gap:** `gap-3`(썸네일↔본문) · `gap-2`(칩/인라인) · `gap-1`~`1.5`(아이콘↔텍스트)
- **리스트 간격:** 카드형 `space-y-3` · 콤팩트/폼 `space-y-2`
- **모달 / 풀스크린 / 빈 상태:** `p-6`
- **하단 탭바 확보:** 본문 `pb-24`

> 요약: **4 / 8 / 12 / 16 / 20 / 24** 의 6단계만 쓴다고 보면 됨. 새 화면도 이 단계 안에서 고르면 자동으로 톤이 맞는다.

- 금지선: 외형·체중·Before/After·비교 압박·사용자 대상 광고. (브랜드 컨셉 `docs/UIUX_REDESIGN.md` 참조)

## 12. 판단 규칙 16 (Logic over taste)

UI 는 감이 아니라 **다시 쓸 수 있는 규칙**으로 정한다. 기본(정보 구조·상호작용 구분·명암비·타이포)을 먼저 바로잡고, 장식은 그다음이다.

| # | 규칙 | 도담에서의 모습 |
| --- | --- | --- |
| 1 | **여백으로 묶는다** — 관련 요소는 가깝게, 정렬로 그룹화. 테두리·박스는 최후 수단 | 카드 안을 선으로 나누기 전에 `gap` 부터 조정 |
| 2 | **같은 기능 = 같은 모양**, 다른 기능 = 다른 모양 | 누를 수 없는 것이 버튼처럼 보이면 안 됨 |
| 3 | **위계가 분명하게** — 크기·명암·간격·위치로. 흐리게 봐도(squint) 핵심이 보여야 함 | 주요 행동 1개가 가장 두드러짐 |
| 4 | **의미 없는 장식 제거** — 선·색·배경·테두리·애니메이션 | §13 참조 |
| 5 | **색은 역할에만** — 흑백으로 시작, 브랜드색은 링크·버튼 등 **상호작용 요소**에 | 제목·장식에 에메랄드 칠하지 않음 |
| 6 | UI 요소 명암비 **≥ 3:1** (WCAG AA) | 사진 위 아이콘은 불투명 배경 |
| 7 | 텍스트 명암비 — 18px↓ **≥ 4.5:1**, 18px↑ bold·24px↑ **≥ 3:1** | `text-gray-400` 은 본문에 쓰지 않음. ⚠️ 예외: 브랜드 초록 버튼·글자는 현행 유지 결정(§4.1) |
| 8 | **색만으로 상태를 구분하지 않는다** | 아이콘·글자·밑줄 병행 |
| 9 | 산세리프 1종 | Pretendard. 예외: 응원 콜라주 손글씨 `font-hand` |
| 10 | x-height 큰 서체 | Pretendard 로 충족 |
| 11 | 대문자 남용 금지 | 영문 라벨은 sentence case |
| 12 | 굵기는 **regular / semibold / bold** | light 본문 금지 |
| 13 | 순수 검정 금지 | 제목 `gray-800`, 본문 `gray-600` |
| 14 | **긴 글은 왼쪽 정렬** | 가운데 정렬은 제목·짧은 한 줄만 |
| 15 | 본문 줄높이 **≥ 1.5** | `text-sm` 토큰 1.55 |
| 16 | 1→15 를 순서대로 적용 | 장식은 마지막 |

### 본인 취향 기록 (관찰된 결정)
- 활성·선택 상태는 **연한 톤** (`bg-emerald-50 text-emerald-700 border-emerald-200`). 진한 `brand-primary` 배경은 "너무 찐함".
- 위계는 **섹션 헤더 > 카드 제목**. 카드 제목이 섹션 헤더보다 굵거나 크면 안 됨.
- 콘텐츠는 가장자리에 가깝게 (페이지 좌우 16px 안팎). 바깥 여백이 좁아 글자가 잘리면 즉시 결함.
- **틀(배너·링·카드) 크기는 바꾸지 않고 글자를 줄여 맞춘다.** 크기가 바뀌면 위계가 무너진다 (2026-09-15 결정).

## 13. 도담에서 하지 않는 것 (Anti-patterns)

AI 가 "예쁘게" 만들 때 꺼내는 흔한 모양, 그리고 우리가 실제로 겪은 실패. **하지 않는 이유와 대신 할 것**을 같이 적는다.

| # | 하지 않는 것 | 이유 | 대신 |
| --- | --- | --- | --- |
| 1 | **보라·남색·무지개 그라데이션**, 네온 글로우 | 가장 흔한 "AI 티". 브랜드는 에메랄드 | 그라데이션은 **Primary CTA(emerald→teal)** 와 헤더 연한 틴트에만 |
| 2 | **똑같은 카드 3~4개를 나란히** (아이콘+제목+설명 반복) | 모두 같은 무게 = 위계 없음 (규칙 3) | 가장 중요한 하나를 크게, 나머지는 목록 |
| 3 | 카드 안에 카드, **테두리+그림자+배경 3중** | 장식 누적 (규칙 1·4) | 한 겹만. 안쪽은 여백과 정렬로 묶기 |
| 4 | **이모지를 UI 아이콘으로** | 기기마다 모양이 달라지고 싸 보임 | `public/icons` 3D 아이콘 → 없으면 lucide 선 아이콘 → 이모지는 폴백·사용자 콘텐츠만. 섹션 제목은 **자리별 구분**(§3): 참여자 화면=3D, 모달·운영자 도구=글자만 |
| 5 | 모든 걸 **가운데 정렬** | 긴 글 가독성 저하 (규칙 14) | 왼쪽 정렬. 빈 상태·축하 화면만 가운데 |
| 6 | 제목·숫자·장식에 **브랜드색** | 무엇을 누를 수 있는지 흐려짐 (규칙 5) | 회색 위계 + 누를 수 있는 곳만 색 |
| 7 | **토큰 밖 임의 값** (`rounded-[40px]`, `text-[17px]`, 새 hex) | 화면마다 미세하게 흔들림 | §2·§4·§6·§7 의 단계 안에서 선택. 없으면 토큰을 추가 |
| 8 | 배너에 **고정 높이 + 데이터 속 `\n` 줄바꿈** | 좁은 폰에서 고아 줄·잘림 (3번 반복된 결함) | §14 배너 레시피 |
| 9 | **로딩 중에 "없어요"** 먼저 보여주기 | 1초 깜빡임 (17곳 수정 이력) | `isLoading` 을 빈 상태 분기 맨 앞에 |
| 10 | 등장할 때마다 **튀기기·흔들기**, 이유 없는 반복 루프 | 주의를 훔침, 저사양 폰 버벅임 | §15 — 움직임은 원인과 결과를 설명할 때만 |
| 11 | **AI 말투 카피** — "✨ 놀라운 여정을 시작하세요!", 느낌표 연발, "혁신적인" | 무엇을 하는지 말하지 않음 | **구체적인 동사 + 결과**: "오늘 3km 인증하기", "12명이 응원했어요" |
| 12 | 외형·체중 비교, Before/After, 순위로 압박하는 카피 | 브랜드 금지선 (동행) | 과정·누적·함께를 말하기 |
| 13 | 한 화면에 **주요 버튼 2개 이상** | 무엇을 할지 망설임 | Primary 1 + 나머지는 텍스트·보조 버튼 |

## 14. 실기기에서 배운 규칙 (Hard-won)

디자인은 넓은 폰에서 하고 검증은 좁은 폰에서 안 해서 반복된 결함들. **새 UI 는 아래 기준에서 깨지지 않아야 한다.**

### 기준 기기
- **가로 360px** (갤럭시 노트9·S 시리즈 기본). 아이폰(390~428px)에서 멀쩡해도 통과가 아니다.
- **글자 배율 1.15배** — 안드로이드 앱은 시스템 글꼴 크기를 따라 최대 1.15배까지 키운다(MainActivity `setTextZoom` 상한). 틀 안에 들어가는지 계산한다.
- 구형 브라우저: Tailwind v4 는 Chrome 111+ 필요. 실기기 테스트 전 브라우저 업데이트.

### 레이아웃
- **flex 행의 `input`·`textarea` 에 `flex-1` 을 주면 `min-w-0` 도 같이.** 폼 요소는 `min-width:auto` 라 안 줄어들어 옆 버튼을 화면 밖으로 민다. 옆 버튼은 `flex-shrink-0`.
- **화면 하단 고정 요소**는 `padding-bottom: max(env(safe-area-inset-bottom), 기본값)`. 바닥에서 띄운 요소는 `mb-[env(safe-area-inset-bottom)]`. 안드16 + 삼성 One UI 에서 내비게이션 바에 깔림(순정 에뮬로는 재현 안 됨). 인셋 0 기기에선 화면이 바뀌지 않아 부작용 없음.
- 모바일 `input/textarea/select` 는 16px (iOS 포커스 줌 방지).
- **`App.css` 에 레이어 밖(unlayered) 요소 리셋 금지** (`p{margin:0}` 등). Tailwind v4 에서 레이어 밖 규칙이 유틸을 항상 이겨 `mb-*`·`text-white` 가 무력화된다. 필요하면 `@layer base { }` 안에.

### 텍스트 배너 레시피 (일러스트 옆 글자)
- **배너 높이는 고정, 글자를 줄여 맞춘다.** `min-h` 로 늘리지 않는다.
- 배너에 `@container`, 제목 `text-[clamp(11.5px,3.5cqi,13px)] leading-[1.25] line-clamp-2`, 부제 `text-[clamp(10px,2.9cqi,11px)] leading-[1.35] line-clamp-2`.
- 데이터에 `\n` 넣지 않기, `whitespace-pre-line` 쓰지 않기.
- 제목·부제·배지 **전부** `break-keep` (한쪽만 넣는 실수가 잦음).
- "배지 + 2줄 + 2줄" 최악의 합이 (배너 높이 − 24px) 이하인지 계산.

### 오버레이·모달
- 새 오버레이는 `useBodyScrollLock(isOpen)` (iOS 배경 스크롤 방지) + `useBackButtonClose` (하드웨어 뒤로 = 닫기).
- 중첩 모달은 뒤로가기 경쟁을 주의 — 안쪽이 닫힐 때 바깥까지 닫히면 `useBackButtonClose` 타이밍부터 의심.

### 사진 입력
- 파일 선택 직후 **`prepareImageFile()`** 필수 (HEIC 변환·검사). `file.type` 검사만으로는 안드로이드에서 깨진다.
- 바로 촬영이 필요하면 `capture="environment"` 를 붙인 **별도 input + 별도 버튼** (안드13+ 사진 선택기엔 카메라가 없음).
- 크롭은 기본 「틀을 꽉 채움」(`minZoom=1` + `objectFit="cover"`). 여백 배치가 목적인 곳만 예외.

### 데이터 상태
- 빈 상태 앞에는 **반드시 로딩 분기**: `isLoading ? <LoadingState/> : items.length===0 ? <EmptyState/> : …`. 파생 상태는 관련 쿼리 전부 `||` 로 묶어 가드.

## 15. 움직임 (Motion) — 2026-09-22 확정

비교 페이지로 속도별 재생을 직접 보고 정했다. **새 작업부터 이 값을 쓰고, 기존 코드는 손볼 때 맞춘다.** (2026-09-22 기준 기존 코드는 0.18~0.5초로 제각각. 공용 `Modal` 은 0.18초.)

### 시간 3단계
| 단계 | 시간 | 용도 | 이징 |
| --- | --- | --- | --- |
| **빠름** | **0.15초** | 버튼 누름 반응, 토글, 칩 선택 | ease-out |
| **기본** | **열기 0.3초 · 닫기 0.2초** | 모달·바텀시트, 탭 전환, 목록 추가·삭제 | 열기 ease-out · 닫기 ease-in |
| **연출** | **0.8초** | 인증 완료 축하, 성취, 숫자 카운트업 | spring 또는 ease-out |

- 닫기는 열기보다 **짧게**. 사용자는 닫는 순간 이미 다음 일을 원한다.
- framer-motion 값: 빠름 `{ duration: 0.15, ease: 'easeOut' }` · 열기 `{ duration: 0.3, ease: 'easeOut' }` · 닫기 `{ duration: 0.2, ease: 'easeIn' }` · 연출 `{ duration: 0.8 }`.
- `transform`·`opacity` 만 움직인다 (레이아웃 속성 금지). 노트9 같은 저사양 폰에서 끊기면 연출을 줄인다.

### 원칙
1. **움직임은 무언가를 설명할 때만** — 어디서 왔는지(시트가 아래에서), 무엇이 바뀌었는지(점수 증가), 내 행동이 먹혔는지(누름 반응). 설명할 게 없으면 움직이지 않는다.
2. **축하 연출은 사용자 행동 직후에만** (인증 제출, 완주, 마일스톤). 화면을 열었다는 이유만으로 터지지 않는다.
3. **반복해서 빛나는 넛지는 허용, 단 조건부** (2026-09-22 결정 — 비교안: 반복 없음 / 계속 빛남 / 3번 후 멈춤 → 「계속 빛남」 선택)
   - 한 화면에 반복 넛지는 **하나만**
   - **행동하면 사라진다** (예: 첫 인증을 하면 「첫 인증」 빛남 종료)
   - 「동작 줄이기」 사용자에게는 멈춘다
   - 의미 없는 장식용 반복(둥둥 떠다니기 등)은 금지
   - 실험 과제: 「3번 빛나고 멈춤」이 더 효과적인지(익숙해져서 안 보게 되는 현상) 나중에 데이터로 비교
4. **「동작 줄이기」(`prefers-reduced-motion`) 존중 필수** — 연출은 즉시 최종 상태로.
   - ✅ 2026-09-22 적용: `App.jsx` 최상단 `MotionConfig reducedMotion="user"`.
   - ⚠️ **전역 설정이 멈추는 건 위치·크기·회전·확대뿐이다.** 그림자·투명도·색 반복은 계속 돈다 (framer-motion 이 `positionalKeys` 만 즉시 처리 — 라이브러리 코드로 확인).
     → 그런 애니메이션은 컴포넌트에서 `const reduceMotion = useReducedMotion()` 으로 직접 분기한다. 반복 빛남은 **고정 글로우**로, 색종이류는 **렌더하지 않음**, 등장 연출은 **건너뛰고 완료 콜백 호출**.
   - 훅은 early return **앞에** 둔다 (rules-of-hooks — 그 뒤에 두면 개수 0↔1 전환 시 화면이 죽는다).
   - 적용 파일: OperatorTodoBanner · EndReportBanner · OperatorReviewBanner · Confetti · PodiumTop3(폭죽) · WizardIntro · Step2Type(ClassDemo).
   - 검증법: ① 안드로이드 전달 — 에뮬에서 `settings put global animator_duration_scale 0`(+transition·window) 후 **앱 재시작**, 디버그 빌드 웹뷰에 CDP 로 `matchMedia('(prefers-reduced-motion: reduce)').matches` 확인 (adb 로 바꾸면 앱이 켜진 채로는 반영 안 됨). ② 동작 — 개발 서버 + 헤드리스 크롬 `Emulation.setEmulatedMedia` 로 두 모드에서 값 샘플링.

### 15.5 상시 반복 모션의 예외 — 아바타 불꽃 (2026-10-05 확정)

원칙 3은 「장식용 무한 반복 금지」지만 **아바타 뒤 불꽃**(`FlameAura`)은 예외로 둔다.
**근거**: 불꽃은 넛지가 아니라 **상태 표시**이고, 「타오른다」가 그 상태의 의미 자체다. 멈춘 불은
정보를 잃는다. 대신 아래 규칙으로 소란스러움을 묶는다.

- **단계가 올라갈수록 세진다** — 움직임 자체가 정보다(1주=잔잔 / 3주 / 6주=격렬).
  `LEVEL_MOTION` 의 speed·amp·lat·spread·glow 배수 한 곳에서만 조절한다.
- `transform`·`opacity` 만. 랭킹은 한 화면에 수십 행이라 **SVG `filter`(블러)·`<animate d>`(경로 재계산) 금지** — 깊이는 그라데이션 3층으로 낸다.
- 「동작 줄이기」면 `animation: none`. **정지 상태가 곧 승인된 모양**이어야 한다.

**다시 논쟁하지 않도록 — 설계에서 배운 제약 3가지**

1. ⚠️ **위로 솟는 쪽에는 예산이 없다.** 혀가 커지면 리스트 윗줄·카드 윗변을 덮는다(아바타 40px
   기준 한도 20px, 3단계가 19px 사용). 「더 활활」은 **아래로 더 꺼지게 / 좌우 / 무질서 / 밝기**로
   낸다. 진동대를 **위에 매달고 아래로 늘어뜨리면** 변동 폭을 3배로 키워도 윗변 예산을 안 쓴다.
2. ⚠️ **띠(층)마다 주기·시작시점을 다르게 하면 안 된다.** 위상이 어긋나는 순간 속불이 바깥
   테두리를 뚫고 나온다(측정 2.9px). 층 분리는 **세로 진폭 차등**으로만 낸다 — 그건 거의 공짜다.
3. 🔴 **`rotate` 와 `skewX` 는 부호가 반대여야 한다.** 혀 끝은 회전 원점보다 위라 `+skewX` 는 끝을
   왼쪽, `+rotate` 는 오른쪽으로 민다. 같은 부호면 서로 지워져 **움직임이 절반으로 죽는다**(실제로
   이 버그 때문에 「활활 타는 느낌이 없다」가 나왔다). `verify-css.mjs` 가 재발을 막는다.

**검증 방법** — CSS 애니메이션은 정지 렌더로 판정이 안 된다. 실제 컴포넌트를 `react-dom/server` 로
렌더 → 키프레임 시점 transform 을 주입 → resvg 로 PNG → **온이언 스킨(여러 시점 윤곽선 겹침)** 으로
궤적을 본다. 작은 크기는 **실제 기기 픽셀로 래스터화한 뒤 확대**해서 봐야 한다(벡터를 키우면 24px
느낌을 못 본다). 다만 **체감 속도는 실기기에서만 판정된다.**

## 17. 사용자 상황별 UX 패턴 — 2026-10-01 추가

일반 UX 원칙(기다림·실수·온보딩·커뮤니티·동기 설계)에서 **도담에 아직 없던 것만** 골라, 퍼소나 v2(`docs/BRAND_PERSONA.md`)에 맞게 바꿔 적었다.
- 「지금」 칸은 2026-10-01 코드 실측이다. 「규칙」은 이번에 정한 기본값이며, 본인이 뒤집으면 여기를 고친다.
- §15 와 같이 **새 작업부터 적용하고, 기존 코드는 손볼 때 맞춘다.**
- 일반 원칙 중 **버린 것**과 이유는 §17.7 에 남긴다. 같은 제안을 다시 하지 않기 위해서다.

### 17.4 온보딩 — 누구에게 어떤 유형을

| 대상 · 순간 | 유형 | 규칙 |
| --- | --- | --- |
| 운영자 · 첫 프로그램 만들기 | **샌드박스 + 점진** | 마법사가 기본값으로 채워진 판을 주고, 운영자는 바꾸고 싶은 것만 바꾼다. 만든 뒤 환영 투어는 켠 기능만(✅ 적용됨) |
| 참여자 · 초대 링크로 가입 | **최소 강제** | 꼭 필요한 것(약관·닉네임)만 받고 바로 「오늘 할 미션」 화면으로. 기능 소개 슬라이드 없음 |
| 누구나 · 처음 쓰는 기능 (팀·리포트 등) | **점진** | 처음 들어간 순간 1회만 짧은 안내. 「이걸 누르세요」가 아니라 무엇이 좋아지는지 |
| 운영자 · 복잡한 도구 (통계·심사) | **상시 도움말** | 제목 옆 작은 「?」. 자동으로 뜨지 않음 |

- 슬라이드형 안내는 **3~5장, 결론부터, 진행률과 건너뛰기 필수.**
- 문구: 기능(스펙)이 아니라 이득을 말한다. 입력을 요구할 때는 이유를 같이 쓴다 (「닉네임은 같은 프로그램 사람들에게 보여요」). 길면 남은 양을 말한다 (「2가지만 더 정하면 끝나요」).
- 판정 질문 3: ① 내가 찾던 게 맞나 ② 지금 바로 뭔가 할 수 있나 ③ 믿고 시간을 써도 되나.

### 17.6 동기 설계 (게이미피케이션) — 일반 처방을 도담식으로 바꾼 표

일반 게이미피케이션 처방 중 퍼소나 원칙 3(비교 없이 과정을 센다)·4(숫자를 부풀리지 않는다)와 부딪치는 것은 **같은 심리를 정직한 방법으로** 푼다.

| 마찰 지점 | 일반 처방 | 도담식 |
| --- | --- | --- |
| 시작이 막막함 | 처음부터 20% 진행된 것처럼 | **실제로 끝낸 단계**로 시작한다. 가입·참여 신청을 1단계 완료로 체크. 가짜 진척 금지 |
| 중간이 지루함 | 미완성 상태를 강조 | 끝까지 남은 양 대신 **이번 주 칸**을 채우게 한다 (작은 단위의 완결) |
| 막판 피로 | 진척 바를 가속 | 바는 실제 비율 그대로. 남은 양을 말로 「3번 남았어요」 |
| 하루 빠짐 | 연속 기록이 깨지는 공포 | **알리지 않는다.** 누적으로 바꿔 보여준다 (퍼소나 4-6) |
| 기대감 | 랜덤 보상 (양·시점·내용) | 확률형 보상 없음. 예측 못 한 기쁨은 **운영자 응원**이 맡는다 (사람이 보내므로 자연스럽게 예측 불가) |
| 숫자에 의미 | 「숲의 에너지가 채워졌어요」 | 평소엔 「인증했어요 · +10P」로 담백하게, 이정표·첫 인증에서만 서사 (퍼소나 원칙 2). 정원 메타포는 「물=인증, 햇빛=출석」 |
| 긴급성 | 타이머·FOMO·「거의 매진」 | 마감은 **사실만** (「오늘 밤 11시 59분까지」). 카운트다운은 실제 정원이나 마감이 있는 예약(클래스·결제)에만, 「놓치면 사라져요」 류 압박 문구 없이 |

- 넣기 전 판정 질문: **이 보상이 인증(핵심 행동)을 하게 만드는가?** 재밌어 보이기만 하면 넣지 않는다.
