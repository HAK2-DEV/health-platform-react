# 제보·버그 로그 (도담)

> **원칙: 제보가 들어오면 «즉시» 한 줄 남긴다. 고치는 건 그다음이다.**
> 나중에 기억으로 복원하려 하면 반드시 빈약해진다. 이 로그는 두 군데에 쓰인다.
> ① 개발 트리아지 ② 프로덕션 액세스 신청서의 「의견 요약」([PLAY_STORE_RELEASE.md](PLAY_STORE_RELEASE.md) 6-0(b)).

## 접수할 때 반드시 같이 묻는 것

코드를 오래 노려보는 것보다 **기기와 재현 조건을 먼저 묻는 편이 훨씬 빨랐다**(2026-09-17 두 번 확인).

1. **기기·OS** — 노트9(안드10)인지 S25인지에 따라 원인이 완전히 달라진다.
2. **화면 버전** — 계정 설정 맨 아래 「앱/웹 · 화면 버전 XXXX · 글자 ×N」 줄을 캡처해 달라고 한다.
   업데이트 직후 첫 실행은 서비스워커 때문에 **옛 번들이 도는 일이 있어**, 이 줄이 없으면 이미 고친 걸 또 쫓게 된다.
3. **무엇을 하다가** — 화면 이동 순서 그대로. 「사진 고르고 돌아오니」처럼 앱이 잠깐 백그라운드로 간 정황이 결정적일 때가 많다.
4. **스크린샷** — 글자 잘림·버튼 가림은 말로 설명하기 어렵다.

## 상태 표기

`접수` → `재현` → `수정` → `배포` → `확인`(제보자가 사라졌다고 확인) / `재현실패` / `보류`

**「수정」과 「확인」은 다르다.** 재현하지 못한 채 고친 것은 `배포` 까지만 적고,
제보자가 다시 확인해 주기 전에는 `확인` 으로 올리지 않는다.
